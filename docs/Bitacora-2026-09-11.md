## 2. Problema mayor — el último Metamod rompe CSS (API 017 vs 018)

Tomar el snapshot más nuevo de Metamod (git1467) **dejó el gungame muerto**. El 2026-09-08 Metamod
bumpeó la SourceHook API a **018** (commit *"Bump MMS Api version, and min load version"*, primer
snapshot afectado: **git1460**). CSS 1.0.374 salió el **2026-09-07**, compilado contra **017**.

Lo traicionero es el síntoma: el server levanta normal, carga el mapa, responde RCON, spawnea bots.
Nada grita. Las señales reales:

- `meta list` → `[01] <ERROR> CounterStrikeSharp (v1.0.374 @ 6c02f47)`
- `css_plugins list` → `Unknown command 'css_plugins'!`
- cero líneas nuevas en `addons/counterstrikesharp/logs/log-all*.txt`

El mensaje de error **solo aparece recargando el plugin a mano** por RCON:

```
meta unload 1
meta load addons/counterstrikesharp/bin/win64/counterstrikesharp
→ Failed to load plugin ... (Plugin uses old SourceHook Metamod build,
  probably 1.12.x or an early 2.0 version (17 < 18).)
```

**Fix aplicado:** bajar a **git1411** (2026-08-31, último con API 017).

**El mismo corte parte MultiAddonManager**: v1.6 (2026-09-09) exige 018 → con git1411 quedaba ella en
`<ERROR>`. Se usa **v1.5.4** (2026-08-18). O sea: *o* todo en 017, *o* todo en 018 — no se mezcla.

> Regla: antes de subir Metamod, confirmar que la release de CSS ya compile contra la API nueva.
> El snapshot "latest" de mmsdrop no es una recomendación.

## 3. Problema — mapas Workshop en loop de recarga

Al cambiar a `fy_snow` (Workshop 3592238209) el mapa entra en **bucle de recarga de ~1 segundo**:
`loaded` → `OnMapEnd` → `loaded` → … Resultado: 156 "Loading config" y 49 cargas de mapa en 5 minutos,
bots reconectando sin parar y **cero kills**. Fácil de confundir con un bug de gungame; no lo es.

Causa: el server corre `sv_lan 1` sin GSLT → **no está logueado en Steam** → no puede montar addons del
Workshop. La pista estaba en el log de Metamod desde el boot:

```
[MultiAddonManager] DownloadAddon: Addon download for 3766168370 failed to start,
addon ID is invalid or server is not logged on Steam
```

Afecta a los **3 mapas Workshop del pool**: `fy_snow`, `fy_iceworld`, `aim_map`.
Salir del loop: `changelevel` a un mapa stock por RCON. Para probarlos de verdad hace falta GSLT
(`sv_setsteamaccount`) y `sv_lan 0`.

Nota positiva: el flujo **fin de partida → GG1MapChooser → cambio de mapa** se disparó solo y eligió
mapa del pool. La mecánica funciona; lo que falla es montar el mapa elegido.

## 4. Problema — `sv_hibernate_when_empty` no persiste

`server.cfg` tiene `sv_hibernate_when_empty 0`, pero al consultarlo por RCON devolvía `true` y el
server dormía con 10 bots dentro (mundo congelado, cero eventos). Mismo gotcha que los cvars de partida:
el gamemode los pisa después de `server.cfg`. Se despertó por RCON para validar, pero **no persiste
entre mapas** — su lugar correcto es `cfg/gamemode_casual_server.cfg`, junto a los `mp_*`.

## 5. Cosas menores que conviene recordar

1. **RCON bindea la IP de una interfaz virtual**, no `127.0.0.1`. Hoy fue `172.28.32.1` (Hyper-V/WSL);
   el 17-jul era `192.168.1.128`. Sacarla de `netstat -ano | grep 27015` antes de asumir.
2. **`-condebug` no genera `csgo/console.log`** con este stack: el output termina en
   `addons/metamod/console.log` (Metamod es el `DEFAULT_WRITE_PATH`). Ahí está el boot completo.
3. El submódulo `GunGameAPI` **sigue en net8.0 / CSS 1.0.330** — el CLAUDE.md afirmaba que se había
   bumpeado, era falso. Compila igual referenciado desde un net10.0; se deja como está.
